## 1. Overview

Crear el formato y las herramientas de preparación y validación de paquetes habituales sin dependencias sin cambios. Reconocer la instalación antigua mediante evidencia verificable. No modifica una instalación cliente ni prepara un catálogo a partir de una versión asumida. Realiza REQ-008 mediante ADR-012 y ADR-013.

## 6. Acceptance and Dependencies

- Se dispone de formato, constructor y verificador comprobados; los paquetes habituales no incluyen datos/secretos ni distribuciones de dependencias sin cambios. releaseId repetido con contenido distinto se rechaza.
- AC-014 y AC-108 deben tener evidencia suficiente del alcance de este paquete. AC-015, AC-016 y AC-110 se completan de forma integrada con WP-007 y WP-009; cerrar las herramientas no certifica una actualización cliente.
- TSK-019 es el primer entregable para WP-007. El constructor puede verificarse con candidatos/instalaciones sintéticos; una entrega real requiere el ejecutable identificable de WP-007 y el cierre de integración de WP-009. No existe dependencia circular de cierre entre ambos paquetes.
- La fase Windows de TSK-022 usa el entorno disponible de WP-010; las validaciones estáticas pueden comenzar antes. Falta de evidencia sobre una instalación concreta bloquea su admisión como origen, no el desarrollo del verificador.
- Quaestor debe vincular los criterios con casos y evidencia antes de declarar cierre. La revisión de planificación inicial no ejecutó pruebas; el avance y la evidencia parcial posteriores se registran a continuación.

Se conserva el instalador inicial.
- TSK-022: ejecución nativa con 51 comprobaciones satisfactorias sobre fixtures, incluida unión NTFS, ZIP antiguo y rechazo de payload/configuración/dependencias.
