## 6. Acceptance and Dependencies

- TSK-023 y TSK-025 consumen el contrato de entrega de TSK-019/WP-006; no necesitan que una actualización integrada esté ya aceptada.
- Arrancar en Windows no aplica migraciones implícitas. Un historial incompleto o incompatible impide servir negocio. Los metadatos protegidos no sustituyen autenticación ni revelan configuración privada.
- AC-023 requiere rechazo antes de persistir: interfaz deshabilitada, proceso detenido de forma transitoria o lock liberado no son evidencia suficiente. AC-022 y AC-109 requieren también integración posterior con WP-008 y WP-009.
- Verificar con la base de autorización exclusiva existente de WP-003, sin copiar secretos ni promover su estado general. La guardia no habilita acceso a otro usuario ni a un registro del cliente con una capacidad de diagnóstico.
- WP-010 proporciona Windows aislado para las comprobaciones de servicios/reinicio; pruebas de código contenidas pueden empezar antes. La transición antigua necesita orígenes admitidos por WP-006.
- No se cierra sin evidencia aplicable y revisión requerida por TMP/estrategia; esta revisión de planificación no ejecuta casos.

### Avance de implementación — 2026-10-11

- TSK-023: identidad compilada, release-info sin DB/auth, migración explícita y arranque con comprobación exacta de historial SQLx. Instalación inicial y desarrollo usan preparación explícita. No se reconstruyó ni ejecutó el instalador completo en esta etapa.
- TSK-024: guardia persistente, rechazo HTTP 503 antes de escritura, autenticación exclusiva y capacidades de diagnóstico ligadas a operación, instancia y registros sintéticos propios. Un bloqueo nativo compartido cubre la transacción; publicar fase exige exclusión.
- TSK-025: lanzador estable con selector/inventario comprobados y primitivas administrativas de control, captura y restauración de opciones SCM. Se compiló la interoperabilidad nativa y se verificaron estructuras; no se modificaron servicios Windows reales ni se probaron reinicios del equipo.
- TSK-026: 11 pruebas Rust satisfactorias y [15 comprobaciones de control](../../tests/artifacts/updates/control-20261011T142516097Z-edf1a051/report.json). [18 escenarios de integración](../../tests/artifacts/updates/runtime-2026-10-11T14-25-25-816Z-bd0ee24f/report.json) con ejecutable compilado y PostgreSQL nativo aislado: historial incorrecto, migración explícita, permisos, guardia, diagnóstico, revocación/reinicio de API y bloqueo cruzado PowerShell/Rust. Autenticación mediante JWKS sintético; no acredita Keycloak ni portal reales.
- Evidencia parcial: no PASS de familias TMP, aceptación de requisitos ni cierre del paquete. WP-010 debe aportar entorno representativo para servicios/reinicio y revisión independiente. WP-008/009 deben integrar copia, recuperación y actualización completa. El catálogo antiguo sigue sin revisar; preflight vivo incompleto. La matriz espera Vestigator y el diseño mantiene estado de borrador.
- El chequeo de infraestructura Docker falló por servicios no disponibles ([informe](../../tests/artifacts/infra-2026-10-11T13-38-24.700Z.json)); las pruebas nativas aisladas no acreditan su reparación. Conservar informes ignorados por Git para revisión, sin exportar clusters ni capacidades privadas.
